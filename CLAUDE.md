# MusicHelper

Music website: Vite + React 19 + TypeScript + TanStack Router (file-based routes) + MUI 7.
npm workspaces: `musiclib` (music theory library) and `frontend` (the site).
Deployed to GitHub Pages under the base path `/MusicHelper/`. Work happens on `dev`.

## Two independent sections

The site has two sections that must stay independent of each other:

- **Theory** (`/scales`, `/chords`): scale and chord tools, with sound and its own settings drawer.
- **Practice** (`/practice/*`): sheet-music practice tool, with its own pages and settings.

```
frontend/src/
  routes/
    __root.tsx        shared only: search-param validation, <HeadContent/>, <Outlet/>
    index.tsx         "/" redirects to /scales
    _theory/          pathless layout (route.tsx) + scales.tsx, chords.tsx
    practice/         layout (route.tsx) + practice pages
  features/
    theory/           code used only by the theory pages
    practice/         code used only by the practice pages
  components/         code shared by both sections (AppHeader, 404, Error)
```

Each section layout (`route.tsx`) renders the shared `AppHeader` with its own nav links and right-side actions.
Set page titles with the route's `head` option.

### Practice section (`features/practice`)

- `engine/`: MusicXML parser, timeline, repeats, grading, wait-mode stepping, sight-reading generator. Plain TypeScript.
- `midi/`: input/output interfaces, Web MIDI, computer keyboard, scheduler (Web Worker tick), thru, panic. Plain TypeScript.
- `osmd/`: the only module that uses OpenSheetMusicDisplay.
- `session/`: the controller that runs a practice run; `player/`, `library/`, `settings/`, `sightreading/`, `ui/`: React.
- Storage: IndexedDB via Dexie (`storage/db.ts`); settings in a zustand store under `music-helper:practice:settings`.
- There is no built-in sound: everything goes out as MIDI. Full spec: `docs/practice-spec.md`.
- ESLint enforces the theory/practice boundary and keeps React, MUI and OSMD out of `engine/` and `midi/`.

## Rules

- `features/practice` must never import from `features/theory`, and `features/theory` must never import from `features/practice`.
- Code both sections need goes in `frontend/src/components/` or in `musiclib`.
- Never rename or change existing localStorage keys (`music-helper:*`). Users' saved settings depend on them. Practice settings use new keys.
- `frontend/src/routeTree.gen.ts` is generated by the TanStack router plugin. Don't edit it by hand.
- Never run `npm run deploy`, and never push to `main` or `gh-pages` from a session. Deploying is done by hand.

## Commands

- `npm install`, then `npm run build` (builds `musiclib`, then `frontend`)
- `npm run lint`
- `npm test` (builds `musiclib`, then runs the Vitest unit tests in `frontend`)
- `npm run dev --workspace frontend`
- `npm run test:e2e --workspace frontend` (Playwright smoke tests; first run `npx playwright install chromium`)
